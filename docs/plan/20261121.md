# BookCars 中国市场用车服务改造计划（含地图服务）

日期：2026-11-23（首版 2026-11-21）。代码基线：BookCars `9.7.0`，本计划随同地图改造一起提交（`f186c021`）。
对标依据公开资料与实际可验证的代码状态；涉及资质、费率与商户承接条件的结论，以合作门店与主管部门的书面确认结果为准。

本次工作目标：① 全面盘点现有功能与中国用车市场的差距；② 给出**最佳最小改造**路径（复用现有前后端与数据模型，不做推倒重建）；③ 完善地图服务，接入中国境内最合适的地图服务；④ 对标国内平台；⑤ 更新本计划。

## 二、地图服务专项（本轮已落地 + 后续）

### 2.1 原状与问题

- 唯一地图实现是 `frontend/src/components/Map.tsx`（react-leaflet 5 + leaflet 1.9.4 + leaflet-boundary-canvas），被首页、搜索页、结账页、网点页、地图弹窗共用。
- 底图硬编码 OSM 瓦片，且**版权声明被注释**；OSM 公共瓦片不允许商用，且在中国境内不可靠。
- 坐标直接使用 WGS-84 裸值落库（`Location.latitude/longitude`），境内商用地图要求 GCJ-02。
- 网点定位靠 `LocationService.getLocationId(name, language)` 做**名称匹配**，没有地理编码与地址检索。
- 后台新增网点只能手填经纬度数字（`admin/src/components/PositionInput.tsx`），运营无法点图定位。
- 全仓库无高德 / 百度 / 腾讯 / 天地图 / Mapbox 任何接入。

### 2.2 选型：高德地图（AMap / Gaode）

选高德作为中国境内主地图服务，理由：

1. **合规**：提供商用授权与审图号，SDK 自带版权水印，符合《地图管理条例》与测绘资质要求；OSM 瓦片无此资质。
2. **覆盖与精度**：境内 POI、道路与限行数据最完整，网点、车场、加油站、充电站 POI 齐全。
3. **能力齐全**：JS API 2.0（地图、地理编码、POI 检索、路径规划、距离矩阵、围栏）+ Web 服务 API v3（可放在后端，服务端签发密钥更安全）。
4. **坐标转换开箱即用**：JS API 提供 `AMap.convertFrom` / `convertTo` 做 WGS-84 ⇄ GCJ-02 互转，避免自研偏移算法。
5. **生态**：与微信小程序、支付宝、滴滴等国内入口协同顺滑。

备选：百度地图（覆盖略弱但 POI 搜索强）、腾讯位置服务（微信生态友好）。本设计把地图抽象为**提供者适配层**，三家的差异被收敛在适配层内，切换成本限于一个适配器。

  - [backend/src/controllers/mapController.ts](../../backend/src/controllers/mapController.ts)、[backend/src/config/mapRoutes.config.ts](../../backend/src/config/mapRoutes.config.ts)、[backend/src/routes/mapRoutes.ts](../../backend/src/routes/mapRoutes.ts)：公开只读接口，已在 [backend/src/app.ts](../../backend/src/app.ts) 挂载。

### 2.4 接口契约

| 接口 | 参数 | 返回 |
| --- | --- | --- |
| `GET /api/map/geocode` | `address`、`city` | `{ address, city, district, township, longitude, latitude }` |
| `GET /api/map/reverse-geocode` | `longitude`、`latitude` | 同上 |
| `GET /api/map/place-search` | `keyword`（≤100 字）、`city` | `MapPlace[]` |
| `GET /api/map/distance` | `from=lng,lat`、`to=lng,lat` | `{ distance(米), duration(秒), source: 'amap' \| 'estimate' }` |

错误约定：参数非法 `400`。未配置或无结果时，正反地理编码返回 `404`，`place-search` 返回 `[]`。高德服务异常返回 `500` 并写日志；距离接口在未配置、无路线或请求失败时返回 `source: 'estimate'`，结账页明确标为预计距离与用时。

### 2.5 配置与上线步骤

后端 [backend/.env.example](../../backend/.env.example)：

```
BC_MAP_PROVIDER=amap        # amap | osm（境内必须 amap）
BC_AMAP_KEY=                # 高德 Web 服务 Key（仅服务端持有）
BC_AMAP_SECRET=             # 可选：数字签名私钥
```

前端 [frontend/.env.example](../../frontend/.env.example)：

```
VITE_BC_MAP_PROVIDER=amap
VITE_BC_AMAP_KEY=            # 高德 Web 端（JS API）Key
VITE_BC_AMAP_SECURITY_CODE=  # 高德 jscode 安全密钥（2021 年起必填）
VITE_BC_MAP_TILE_URL=https://{s}.tile.openstreetmap.org/{z}/{x}/{y}.png
```

后台 [admin/.env.example](../../admin/.env.example)：同前端的 `VITE_BC_MAP_PROVIDER` / `VITE_BC_AMAP_KEY` / `VITE_BC_AMAP_SECURITY_CODE`。

上线顺序：① 高德开放平台申请 Web 端 Key + jscode、Web 服务 Key，主体完成认证与商用授权；② 填入 env 并把 `BC_MAP_PROVIDER` / `VITE_BC_MAP_PROVIDER` 置为 `amap`；③ 后端 `npm run build` 并重启，前端/后台重新构建；④ 用 `__scripts/ui-verify.py` 回归 30 个页面并核对地图水印与审图号；⑤ 境外部署保持 `osm`。

### 2.6 坐标与合规要点

- **落库仍用 WGS-84**（与既有数据、既有移动端兼容），**仅在渲染与地理编码时**转 GCJ-02；后台选点用 `AMap.convertTo` 回落 WGS-84，避免新老数据混用坐标系。
- 高德 JS API 必须先设置 `window._AMapSecurityConfig = { securityJsCode }` 再加载脚本，否则底图鉴权失败。
- 境内上线需确认高德商用授权范围、审图号标注要求、SDK 自带版权水印不得遮挡。
- 关键业务（订单、网点）坐标属个人信息范畴，随《个人信息保护法》处理最小必要原则；离境业务与境内业务的数据不宜混库。

### 2.7 地图仍需补齐的能力（P1/P2）

| 能力 | 用途 | 改造点 |
| --- | --- | --- |
| 前台 POI 选点与地址检索 | 替代当前「名称匹配」选网点 | `frontend/src/components/Map.tsx` 门面增加检索回调，复用 `/api/map/place-search` |
| 距离矩阵与接驾服务 | 异地还车、机场接送报价 | 复用 `/api/map/distance`，扩展为矩阵接口 |
| 城市 / 区域（adcode）运营 | 按城市定价、按区域开城 | `Location` 增加 `adcode` / `cityCode`，检索接口返回并入库 |
| 电子围栏与改价覆盖 | 机场、景区、限行区差异化价格 | 新增围栏模型与服务端计价钩子 |
| 车场 / 加油站 / 充电站 POI | 还车指引、增值服务 | 复用 POI 检索 |
| 轨迹与里程核对 | 还车结算、超时费、违章 | 需要车机或手机定位，不属最小改造范围 |

## 四、最佳最小改造方案

原则：**不重写、不换框架**；模型只加字段不建新表；能力以 `env` 开关灰度；接口保持向后兼容；每一步都可独立上线。

### P0 — 底座（建议 4 周）

| # | 事项 | 改造点（文件级） | 验收标准 |
| --- | --- | --- | --- |
| 1 | 地图服务接入高德（**接口契约与中文结账降级已验证**） | 四个 `/api/map/*` 接口均有契约测试；按高德 v3 路线结构解析驾车距离和用时；结账区分驾车路线与估算 | 本地接口和中文结账已通过。高德真实 Key、境内底图及后台选点仍待联调，联调时再跑 30 页 UI 回归 |
| 2 | 支付一致性与可恢复（**本地扣款恢复测试通过**，Stripe 联调待验） | [backend/src/controllers/bookingController.ts](../../backend/src/controllers/bookingController.ts)：新增 `capturePaymentIntent` / `confirmPendingBooking` / `recoverPendingCapture`，订单先以 `Void + expireAt` 落库占位车源，扣款成功后再 CAS 置为已付并写入 `paidAmount`；[backend/src/controllers/stripeController.ts](../../backend/src/controllers/stripeController.ts) 新增 `webhook`；[backend/src/app.ts](../../backend/src/app.ts) 以 `express.raw` 前置挂载 `/api/stripe/webhook` | 捕获失败不产生「已付未收款」订单（返回 500 且订单仍为待支付）；重复支付幂等（重试可补扣并返回同一 `bookingId`）；已取消的 `paymentIntentId` 复用返回 400 |

### 本轮同时落地的服务端规则（开关控制）

`Setting.enforceBookingRules`（默认关闭，灰度上线）打开后，门店规则由服务端强制执行，非法请求返回 400：

- 租期短于 `minRentalHours` → `The rental duration is shorter than the minimum duration`
- 取车时间不足 `minPickupHours` 提前量 → `The pick-up date is too close`
- 取车、还车分别按对应门店的 `timezone` 校验 `businessHours`，精确到分钟，支持跨午夜。开门时刻可预约，关门时刻不可预约。结账页显示具体哪个时段超出营业时间。未填写或使用非时间段说明的网点继续仅作信息展示。

> 说明：强制校验会让历史测试中「过去日期」的样例全部失败，因此默认关闭，由门店灰度开启；规则实现与开关相互独立。

## 五、风险与合规红线

1. **地图**：境内商用必须使用持牌地图服务并保留授权与审图号；OSM 瓦片不得用于境内商用。
2. **个人信息**：驾驶证、身份证、护照属敏感个人信息，需明确处理依据、最小必要、保存期限与访问控制；归档驾驶证通过鉴权接口下载。临时预览使用客户端选中的文件，部署需配置过期清理。
3. **实名与合同**：国内租车要求承租人实名、双证核验与书面合同；无证或准驾不符不得交车。
4. **支付与押金**：押金退还时效、预授权与免押须有对账与台账；预付功能上线前必须先修 P0-2。
5. **发票**：境内交易需可开具合规发票，主体与税率须明确。
6. **发票与收款主体**：平台代收租金的资质与二清风险，需与有支付牌照的机构合作。
